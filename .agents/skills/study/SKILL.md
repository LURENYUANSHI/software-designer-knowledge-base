# 软件设计师备考学习流

核心原则：**最小考点循环 + 自适应题组 + 真题校准 + 间隔复习 + Study Transaction（学习事务）**。

状态：`⬜ 未开始` ｜ `🟦 学习中/教学完成但待校准` ｜ `🟨 初步掌握，待延迟复测` ｜ `✅ 延迟复测通过`。

## 0. 状态文件架构

长期学习状态采用小文件分片，避免把持续增长的大文件作为高频写入事实源：

- 全局浏览：`00-学习计划/总体进度.md`
- 唯一恢复入口：`00-学习计划/当前检查点.md`
- 模块事实源：`00-学习计划/模块进度/01-...md` ～ `12-...md`（01～12 长期完整保留）
- 学习日志：`15-学习日志/YYYY-MM/DD.md`
- 知识本体：对应章节目录（`01-...` ～ `12-...`）下的考点笔记
- 真题与模考记录：`13-真题与模拟/上午综合/`、`13-真题与模拟/下午设计/`、`13-真题与模拟/真题索引.md`
- **错题调度入口**：`14-错题本/当前复习队列.md`（启动时只读轻量队列）
- 错题索引：`14-错题本/错题索引.md`
- 活动错题详情：`14-错题本/活动错题/错NNN.md`（一题一文件）
- 已归档错题：`14-错题本/已归档/`

### 历史保护门禁
已沉淀的历史日志、模考卷、错题记录与归档文件必须保留，**不得删除、清空或覆盖成摘要**，除非用户明确要求。

## 1. 启动检查（每次进入必做）
1. 读 `00-学习计划/当前检查点.md`。
2. 读当前主线模块 `00-学习计划/模块进度/<模块>.md`。
3. 读 `14-错题本/当前复习队列.md`，检查今天到期、逾期或高优先级的活动错题（默认先花 10–20 分钟处理到期复测）。
4. **只对本轮实际要复测的错题读取详情**（`14-错题本/活动错题/错NNN.md`），不一次性扫描全部历史。
5. 若检查点、模块状态、队列存在不一致，以最新具体记录为准先修复再继续。
6. 向用户汇报到期错题数与当前主线定位，等待用户说「开始」或指定本次目标（如先复测、推进新考点或导入外部刷题错题）。

## 2. 最小考点粒度门禁
一个进度项若包含多个可独立命题的概念，必须拆成最小子考点（如设计模式拆到单个模式、排序拆到单个排序算法）。拆分结果先写入对应模块进度文件，一次只讲当前最小子考点。

## 3. 考点级循环

### 步骤 1 · 定位
报告模块和最小子考点，等用户确认「开始」。

### 步骤 2 · 讲解
固定五段：**定义、要点（含推导/案例）、易错点、真题考法、秒题技巧**。
- 上午考点以概念辨析、计算推导、表格对比和考场秒杀口诀/排除法为主；
- 下午考点（DFD / E-R / UML / 算法 / 设计模式）优先配 Mermaid 图示、Java 代码结构与套路化定位步骤；
- 每次沉淀新考点笔记时，**必须**写入 `## 秒题技巧`，并把高价值通用口诀同步追加到 `00-学习计划/高频秒题技巧速查.md`。

### 步骤 3 · 问答
澄清用户的疑问，用户确认理解后进入答题。

### 步骤 4 · 答题（自适应题组）
从 5 题起：2 道即时理解 + 2 道变式 + 1 道综合迁移，逐题作答、批改、解析。
- 0 错：进入真题校准；
- 1 错：追加 2 道针对同错因的变式题；
- ≥2 错：先针对薄弱点补讲，再追加 3–5 题；同类错误连续出现立即停下补讲。

#### 新错题写入
凡出现知识性错误，立即：
1. 分配下一个 `#错NNN`（按 `错题索引.md` 最大编号 +1）；
2. 创建 `14-错题本/活动错题/错NNN.md`，记录模块、最小考点、首次错误日期、来源、原错因、正确判据、当场补强与延迟复测历史；
3. 将该编号加入 `14-错题本/当前复习队列.md`，安排 `D+1 → D+3 → D+7 → D+14`；
4. 更新 `14-错题本/错题索引.md`；
5. 当场补强可记录，但**不计延迟复测通过**。

#### 真题校准
每个子考点目标通过至少 2 道外部真题（至少 1 道 A/B 级，不编造年份场次；转述须标明来源）。来源不足不阻塞新授，教学闭环完成后标 `🟦 待真题校准`；满足自适应 + 外部校准后可升 `🟨`。

### 步骤 5 · 个人记忆点
主动询问「有没有想记进笔记的个人口诀或踩坑点？」；用户回复后写入考点笔记 `## 我的笔记`（说「没了」则直接沉淀）。

## 4. 错题延迟复测规则

### 4.1 调度阶梯
`D+1 → D+3 → D+7 → D+14`，队列记录明确的下一复测日期与连续通过次数（`0/2`、`1/2`）。

### 4.2 出题门禁
- 必须脱离原解析，出**同错因的换题/变式题**，不得照搬原题或提前泄露答案；
- 同日补强永远不计延迟复测通过。

### 4.3 通过、失败与归档
- 延迟换题答对：有效延迟通过次数 +1，推进下一复测阶梯；
- **连续两次延迟换题答对（2/2）**后标记 `✅` 归档：移出 `当前复习队列.md`，更新 `错题索引.md`，并在错题文件标记归档（或移入 `已归档/`）；
- 复测失败：连续通过次数清零，记录新错因，重新安排 `D+1`；
- 已归档错题若隔日再次答错：重新激活，重新入队。

## 5. 外部刷题 / 模考错题导入流程（如软考达人每日一练）
当用户提供外部刷题链接、截图或错题清单时：
1. 完整提取全部错题（题干、选项、作答、正确答案、解析与图示要点），核对错题总数；
2. 在 `13-真题与模拟/上午综合/`（或 `下午设计/`）新建当次刷题复盘记录，并登记到 `13-真题与模拟/README.md`；
3. 为每道错题分配顺序编号 `#错NNN`，创建 `14-错题本/活动错题/错NNN.md`，统一加入 `当前复习队列.md`（安排 `D+1`）与 `错题索引.md`；
4. 对涉及的新知识点或薄弱点，新建或增量补充对应章节的考点笔记，并更新相关 `模块进度/*.md`、`总体进度.md`、`当前检查点.md` 和当天日期日志；
5. 执行完整 Study Transaction（提交并推送 GitHub）。

## 6. Study Transaction（强制学习事务）
每次最小子考点闭环、复测批次或外部错题导入完成后，必须提交完整事务：
1. 考点笔记（对应章节目录）；
2. 涉及的 `00-学习计划/模块进度/*.md` 与 `00-学习计划/总体进度.md`；
3. `00-学习计划/当前检查点.md`；
4. 当天日志 `15-学习日志/YYYY-MM/DD.md`；
5. 若有新错/复测：`活动错题/错NNN.md` + `当前复习队列.md` + `错题索引.md`；
6. `git add` + 清晰中文 `study:` 前缀 commit + `git push`；
7. 核验 `git status` 干净且远端分支已同步。

只有全部完成才能宣布本次沉淀完成。

## 7. 查看进度
- 「查看进度」：读 `00-学习计划/总体进度.md` + `00-学习计划/当前检查点.md` + 当前模块文件；
- 「查看错题/复测」：读 `14-错题本/当前复习队列.md` + `14-错题本/错题索引.md`，仅按需打开具体 `错NNN.md`。
